    Taikai¶

    1. Introduction¶

    Taikai is an automated architecture testing tool for Java projects. It builds on ArchUnit and adds a large set of ready-made, fluently configurable architectural rules, so that enforcing conventions does not require writing ArchUnit predicates and conditions by hand.

    A Taikai check is an ordinary unit test. It imports your compiled classes, evaluates every configured rule against them, and fails the build when a rule is violated.

    class ArchitectureTest {

  @Test
  void shouldFulfillConstraints() {
    Taikai.builder()
        .namespace("com.company.project")
        .java(java -> java
            .noUsageOfDeprecatedAPIs()
            .fieldsShouldNotBePublic())
        .build()
        .checkAll();
  }
}

    2. Requirements¶

    Requirement Version
    Java 17 or higher
    ArchUnit 1.5.1

    ArchUnit is a regular (compile-scope) dependency of Taikai, so it arrives transitively and you do not need to declare it yourself. Taikai only relies on the stable ArchUnit core API, so a newer patch or minor ArchUnit release normally works unchanged. If you pin a different ArchUnit version in your own build, verify it after upgrading Taikai.

    3. Installation¶

    Taikai belongs on the test classpath only.

    3.1 Maven¶

    <dependency>
  <groupId>com.enofex</groupId>
  <artifactId>taikai</artifactId>
  <version>${taikai.version}</version>
  <scope>test</scope>
</dependency>

    3.2 Gradle¶

    testImplementation "com.enofex:taikai:${taikaiVersion}"

    ArchUnit comes along transitively; no separate declaration is required.

    4. Quick Start¶

    The example below is a complete, runnable test. Every other code sample in this document is a fragment that plugs into this same skeleton (see Section 6).

    import static com.tngtech.archunit.core.domain.JavaModifier.FINAL;
import static com.tngtech.archunit.core.domain.JavaModifier.PRIVATE;

import com.enofex.taikai.Taikai;
import com.enofex.taikai.java.ImportPatterns;
import java.util.List;
import org.junit.jupiter.api.Test;
import org.slf4j.Logger;

class ArchitectureTest {

  @Test
  void shouldFulfillConstraints() {
    Taikai.builder()
        .namespace("com.company.project")
        .failOnEmpty(true)
        .java(java -> java
            .noUsageOfDeprecatedAPIs()
            .noUsageOfSystemOutOrErr()
            .fieldsShouldNotBePublic()
            .methodsShouldNotDeclareGenericExceptions()
            .utilityClassesShouldBeFinalAndHavePrivateConstructor()
            .imports(imports -> imports
                .shouldHaveNoCycles()
                .shouldNotImport(ImportPatterns.shaded()))
            .naming(naming -> naming
                .packagesShouldMatchDefault()
                .classesShouldNotMatch(".*Impl")
                .constantsShouldFollowConventions()
                .interfacesShouldNotHavePrefixI()))
        .logging(logging -> logging
            .loggersShouldFollowConventions(Logger.class, "logger", List.of(PRIVATE, FINAL)))
        .test(test -> test
            .junit(junit -> junit
                .classesShouldEndWithTest()
                .methodsShouldBePackagePrivate()
                .methodsShouldContainAssertionsOrVerifications()))
        .build()
        .checkAll();
  }
}

    5. Core Concepts¶

    5.1 Selecting Classes with a Namespace¶

    namespace is the base package Taikai imports and analyzes.

    Taikai.builder()
    .namespace("com.company.project")
    .build()
    .check();

    5.2 Selecting Classes Directly¶

    Instead of a namespace you can hand Taikai an explicit set of JavaClasses, or a list of class literals.

    JavaClasses classes = new ClassFileImporter()
    .importClasses(ClassToCheck.class);

Taikai.builder()
    .classes(classes)
    .build()
    .check();

    Taikai.builder()
    .classes(ClassToCheck.class, AnotherClassToCheck.class)
    .build()
    .check();

    Warning

    Setting both namespace and classes is not supported and throws an IllegalArgumentException at build() time. Choose one.

    5.3 Namespace Import Modes¶

    Namespace.IMPORT controls whether test classes take part in a check.

    Mode Imports
    WITHOUT_TESTS production classes only
    WITH_TESTS production and test classes
    ONLY_TESTS test classes only

    Each rule group has a default mode, so in practice you rarely set this yourself:

    Rule group Default mode
    java(...), logging(...), spring(...), quarkus(...) WITHOUT_TESTS
    test(...) / junit(...) ONLY_TESTS

    Override it per rule through Configuration:

    .java(java -> java
    .fieldsShouldNotBePublic(Configuration.of(Namespace.IMPORT.WITH_TESTS)))

    5.4 Excluding Classes Globally¶

    excludeClasses(...) removes classes from every rule. It accepts class literals or string patterns.

    Supported string patterns:

    • Fully qualified class name — com.company.project.foo.ClassToExclude
    • Package wildcard (*) — classes directly in that package: com.company.project.foo.*
    • Recursive package wildcard (..) — the package and all subpackages: com.company.project.internal..
    Taikai.builder()
    .namespace("com.company.project")
    .excludeClasses(
        "com.company.project.foo.ClassToExclude",
        "com.company.project.bar.*",
        "com.company.project.internal..")
    .excludeClasses(GeneratedMapper.class, LegacyFacade.class)
    .build()
    .check();

    excludeClasses(...) also accepts criteria, which can exclude classes by annotation or any other property instead of by name. A class matching any of the registered criteria is excluded. This is the typical way to skip generated code everywhere:

    Taikai.builder()
    .namespace("com.company.project")
    .excludeClasses(ClassCriteria.inPackage("com.company.project.generated.."))
    .excludeClasses(ClassCriteria.annotatedWith(Legacy.class))
    .build()
    .check();

    Warning

    Class criteria only see annotations that are kept in the class files. jakarta.annotation.Generated and javax.annotation.processing.Generated, which code generators commonly add, have SOURCE retention, so ClassCriteria.annotatedWith(...) never matches them. Exclude generated code by package, or by an annotation with CLASS or RUNTIME retention.

    To exclude classes from a single rule only, use Configuration instead.

    Warning

    Exclusions, whether by name or by criteria, are only applied on the namespace path, so they take effect only when the classes come from namespace(...). If you supply the classes yourself — globally via classes(...) or per rule via Configuration.of(JavaClasses) — excludeClasses(...) is silently ignored. Filter the JavaClasses before handing them over, or pass the exclusions together with a rule's classes in Configuration.of(JavaClasses, Collection<T>).

    5.5 Failing on Empty Rule Results¶

    By default an ArchUnit rule that matches no classes passes silently. That hides typos in regexes and rules that quietly stopped applying after a refactoring. failOnEmpty(true) turns those into failures.

    Taikai.builder()
    .namespace("com.company.project")
    .failOnEmpty(true)
    .build()
    .check();

    The default is false. Turning it on is recommended for any long-lived configuration.

    5.6 Running the Checks¶

    Both methods evaluate every configured rule; they differ in how they report.

    Method Behavior
    check() Stops at the first violated rule and throws immediately.
    checkAll() Evaluates all rules, aggregates every violation, then throws one combined report. 
    Taikai.builder()
    .namespace("com.company.project")
    .build()
    .check();      // fail fast

    Taikai.builder()
    .namespace("com.company.project")
    .build()
    .checkAll();   // full report

    Prefer checkAll() when introducing Taikai to an existing codebase, so you see the whole backlog in one run. check() gives a shorter, more focused failure once the codebase is clean.

    5.7 Reading the Failure Report¶

    check() propagates ArchUnit's own AssertionError for the first failing rule.

    checkAll() produces an aggregated report with a violation count, a rule count, and the individual violations grouped per rule:

    java.lang.AssertionError: Found 2 Taikai violations for 2 rules!

Rule: Classes should not use System.out or System.err
    Method com.company.project.OrderService.process() calls java.lang.System.out

Rule: Fields should not be public unless they are static
    Field total in class com.company.project.Order is public

    The rule line is the rule's own description, which is also what you grep for when you want to find the configuration that produced a violation.

    Detail lines that come from stock ArchUnit conditions end with the source file and line number, so they are one click away in an IDE:

    Rule: Classes should not have names matching .*Service
    Class <com.company.project.OrderService> has name matching '.*Service' in (OrderService.java:0)

    Rules built on Taikai's own conditions — among them noUsageOfSystemOutOrErr, fieldsShouldNotBePublic, classesShouldImplementHashCodeAndEquals and the logger rules — name the offending element without a location, as in the report above.

    5.8 Per-Rule Configuration¶

    Every rule method has an overload taking a TaikaiRule.Configuration. It overrides the global settings for that one rule: a different namespace, a different import mode, an explicit class set, or additional excluded classes.

    Factory Purpose
    Configuration.defaultConfiguration() Global namespace, WITHOUT_TESTS
    Configuration.of(String namespace) Different namespace
    Configuration.of(Namespace.IMPORT namespaceImport) Different import mode
    Configuration.of(String namespace, Namespace.IMPORT namespaceImport) Both
    Configuration.of(JavaClasses javaClasses) An explicit class set
    Configuration.of(Collection<T> excludedClasses) Exclusions (String patterns or Class<?>)
    Configuration.of(String, Collection<T>) Namespace plus exclusions
    Configuration.of(Namespace.IMPORT, Collection<String>) Import mode plus exclusions
    Configuration.of(String, Namespace.IMPORT, Collection<T>) Namespace, import mode and exclusions
    Configuration.of(JavaClasses, Collection<T>) Class set plus exclusions

    Collection<T> accepts either String patterns or Class<?> literals, but not both in the same collection — the type is decided from the first element. The Namespace.IMPORT plus exclusions overload is the one exception: it takes Collection<String> only, so pass class names there rather than class literals.

    Warning

    A Configuration that does not name an import mode always means WITHOUT_TESTS. It does not inherit the rule group's default. This matters for the JUnit rules, which are the only ones defaulting to ONLY_TESTS: attaching a Configuration for some unrelated reason silently switches them to production classes, where they match nothing and pass.

    // ONLY_TESTS - checks every test method
.test(test -> test
    .junit(junit -> junit
        .methodsShouldMatch("should.*")))

// WITHOUT_TESTS - silently checks nothing
.test(test -> test
    .junit(junit -> junit
        .methodsShouldMatch("should.*", Configuration.of(List.of("com.company.project.Legacy")))))

// ONLY_TESTS restored explicitly
.test(test -> test
    .junit(junit -> junit
        .methodsShouldMatch("should.*",
            Configuration.of(Namespace.IMPORT.ONLY_TESTS, List.of("com.company.project.Legacy")))))

    Pairing this with failOnEmpty(true) turns such a silent pass into a failure.

    .java(java -> java
    .imports(imports -> imports
        .shouldNotImport(ClassCriteria.inPackage("com.company.project.legacy.."),
            Configuration.of("com.company.project.different", Namespace.IMPORT.WITHOUT_TESTS))
        .shouldNotImport(lombok(),
            Configuration.of(Namespace.IMPORT.ONLY_TESTS))))

    .spring(spring -> spring
    .noSelfInvocationOfProxiedMethods(
        Configuration.of(List.of(OrderService.class))))

    5.9 Disabling a Rule Group¶

    Every configurer implements disable(), which clears all rules registered on that configurer. This is mainly useful when a shared profile enables a group that a particular module must not run.

    Taikai.builder()
    .namespace("com.company.project")
    .java(DEFAULT_JAVA_PROFILE)
    .spring(spring -> spring
        .controllers(controllers -> controllers
            .disable()))         // drop every controller rule the profile added
    .build()
    .checkAll();

    Every rule group has disable(): java, imports, naming, logging, test, junit, spring, boot, properties, configurations, controllers, services, repositories, transactional, quarkus, resources, panache and ai.

    disable() cascades to nested configurers: java(...) also clears naming and imports, spring(...) clears all its sub-configurers, quarkus(...) clears resources, panache and ai, and test(...) clears junit.

    5.10 Modifying an Existing Configuration¶

    toBuilder() returns a builder pre-populated from an existing Taikai instance, so a shared base configuration can be adapted per module.

    Taikai base = Taikai.builder()
    .namespace("com.company.project")
    .excludeClasses("com.company.project.SomeClassToExclude")
    .failOnEmpty(true)
    .java(java -> java
        .fieldsShouldNotBePublic())
    .build();

Taikai adapted = base.toBuilder()
    .namespace("com.company.newproject")
    .excludeClasses("com.company.project.AnotherClassToExclude")
    .java(java -> java
        .classesShouldImplementHashCodeAndEquals()
        .finalClassesShouldNotHaveProtectedMembers())
    .build();

adapted.check();

    5.11 Reusable Rule Profiles¶

    A profile is a Customizer<T>, where T is a configurer type such as JavaConfigurer or TestConfigurer. It packages a set of rules that can be applied to many modules or repositories, and it can be combined with project-specific rules.

    private static final Customizer<JavaConfigurer> DEFAULT_JAVA_PROFILE = java -> java
    .noUsageOf(Date.class)
    .fieldsShouldNotBePublic();

private static final Customizer<TestConfigurer> DEFAULT_TEST_PROFILE = test -> test
    .junit(junit -> junit
        .methodsShouldBePackagePrivate()
        .methodsShouldMatch("should.*")
        .methodsShouldContainAssertionsOrVerifications()
        .classesShouldBePackagePrivate(ClassCriteria.nameMatching(".*Test"))
        .classesShouldNotBeAnnotatedWithDisabled());

    Taikai.builder()
    .namespace("com.company.project")
    .java(java -> {
      DEFAULT_JAVA_PROFILE.customize(java);                         // apply the profile
      java.classesShouldBeRecords(ClassCriteria.nameMatching(".*Dto"));  // plus a local rule
    })
    .test(DEFAULT_TEST_PROFILE)                                     // use the profile directly
    .build()
    .checkAll();

    5.12 Adding Custom ArchUnit Rules¶

    Anything Taikai does not cover can be expressed as a plain ArchUnit rule and registered with addRule or addRules. Custom rules participate in check() and checkAll() like built-in ones, and accept the same Configuration.

    ArchRule rule = classes()
    .that().resideInAPackage("..domain..")
    .should().onlyBeAccessed().byAnyPackage("..domain..", "..application..");

Taikai.builder()
    .namespace("com.company.project")
    .addRule(TaikaiRule.of(rule))
    .addRule(TaikaiRule.of(rule, Configuration.of(Namespace.IMPORT.WITH_TESTS)))
    .addRules(List.of(TaikaiRule.of(rule), TaikaiRule.of(anotherRule)))
    .build()
    .checkAll();

    5.13 Selecting with Criteria¶

    Rules that apply to a selection of classes, fields or methods take an ArchUnit DescribedPredicate, so the selection can be expressed precisely and combined freely. The parameter type tells you which factory builds it:

    Parameter type Factory Listed as
    DescribedPredicate<? super JavaClass> com.enofex.taikai.ClassCriteria classes, and types such as forbiddenTypes
    DescribedPredicate<? super JavaField> com.enofex.taikai.FieldCriteria fields
    DescribedPredicate<? super JavaMethod> com.enofex.taikai.MethodCriteria methods

    Passing criteria of the wrong kind does not compile, so a FieldCriteria can never end up in a rule that selects methods.

    Class criteria¶

    ClassCriteria selects the classes a rule applies to. Rules that restrict sets of types, such as noUsageOf, shouldNotImport or methodsShouldNotReturnForClass or fieldsShouldNotBeOfType, take class criteria for those types too, and FieldCriteria.ofType(...) selects fields by class criteria on their type.

    Criterion Matches
    ClassCriteria.annotatedWith(Class<? extends Annotation> annotationType) classes directly or meta-annotated with the annotation; SOURCE-retention annotations never match
    ClassCriteria.annotatedWith(String annotationType) same, by fully qualified name without @
    ClassCriteria.type(Class<?> clazz) exactly the type, without its subtypes, for example Optional
    ClassCriteria.assignableTo(Class<?> clazz) classes extending or implementing the type, directly or indirectly; the type itself does not match
    ClassCriteria.implementing(Class<?> clazz) classes implementing the interface, directly or indirectly; interfaces never match
    ClassCriteria.nameMatching(String regex) the entire fully qualified class name, for example .*Dto
    ClassCriteria.simpleNameMatching(String regex) the entire simple class name, for example OrderDto
    ClassCriteria.inPackage(String packageIdentifier) classes in an ArchUnit package identifier, for example com.company.internal..

    Combine criteria with .and(...) and .or(...), and negate them with DescribedPredicate.not(...). Any other ArchUnit class predicate works as well, for example JavaClass.Predicates.assignableTo(Repository.class).

    .java(java -> java
    .classesShouldBeRecords(ClassCriteria.nameMatching(".*Dto")
        .and(ClassCriteria.inPackage("..api..")))
    .classesShouldBePackagePrivate(ClassCriteria.annotatedWith("jakarta.persistence.Entity")
        .or(ClassCriteria.inPackage("..internal..")))
    .noUsageOf(ClassCriteria.inPackage("..domain.."),
        ClassCriteria.inPackage("com.company.legacy..")))

    The description of the criteria becomes part of the rule name shown in failure reports.

    Class criteria can also exclude classes from every rule with excludeClasses(criteria), which also covers the rules that take no parameters, such as noUsageOfSystemOutOrErr() or fieldsShouldNotBePublic().

    Field and method criteria¶

    Rules that select fields or methods, such as fieldsShouldHaveModifiers or methodsShouldBeAnnotatedWith, take field or method criteria:

    Criterion Matches
    FieldCriteria.nameMatching(String regex) the entire field name, without the declaring class, for example logger
    FieldCriteria.annotatedWith(Class<? extends Annotation> annotationType) fields directly or meta-annotated with the annotation
    FieldCriteria.ofType(Class<?> clazz) fields whose declared raw type is exactly the type; List<String> has the type List
    FieldCriteria.ofType(DescribedPredicate<? super JavaClass> types) fields whose declared raw type matches class criteria
    MethodCriteria.nameMatching(String regex) the entire method name, without the declaring class, for example find.*
    MethodCriteria.annotatedWith(Class<? extends Annotation> annotationType) methods directly or meta-annotated with the annotation

    Every annotatedWith, type, assignableTo, implementing and ofType(Class) criterion also has an overload taking the fully qualified name as a String. Field and method criteria combine like class criteria, and with ArchUnit member predicates such as HasModifiers.Predicates.modifier(PUBLIC). This allows selections that no single rule variant offers:

    .java(java -> java
    .fieldsShouldHaveModifiers(FieldCriteria.ofType(Logger.class), List.of(PRIVATE, STATIC, FINAL))
    .methodsShouldHaveModifiers(MethodCriteria.annotatedWith(GetMapping.class)
        .and(MethodCriteria.nameMatching("find.*")), List.of(PUBLIC)))

    To select fields or methods by their declaring class, use the …ForClass variants, such as methodsShouldBeAnnotatedWithForClass or fieldsShouldHaveModifiersForClass, which take class criteria.

    6. How to Read the Rule Reference¶

    Sections 7 to 11 document every rule. To keep them readable, examples are shown as fragments rather than complete tests. A fragment such as

    .java(java -> java
    .classesShouldBeRecords(ClassCriteria.nameMatching(".*Dto")))

    belongs inside the builder chain from Section 4:

    Taikai.builder()
    .namespace("com.company.project")
    .java(java -> java
        .classesShouldBeRecords(ClassCriteria.nameMatching(".*Dto")))
    .build()
    .check();

    Conventions used throughout the reference:

    • Rules are fluent and chainable; each returns its configurer.
    • Wherever a rule takes an annotation or a type, there are two overloads: one taking a Class<?> literal and one taking a fully qualified name as a String. The String form exists so you can reference types that are not on the test classpath. Only one form is shown per rule.
    • Rules that apply to a selection of classes take a DescribedPredicate<? super JavaClass>, usually built with ClassCriteria, listed as classes. Rules that select fields or methods by name take FieldCriteria or MethodCriteria, listed as fields or methods.
    • Every rule also has an overload with a trailing TaikaiRule.Configuration parameter (see 5.8). It is omitted from the signatures below.
    • Collection<JavaModifier> parameters take ArchUnit's com.tngtech.archunit.core.domain.JavaModifier constants, for example List.of(PUBLIC, STATIC, FINAL).
    • A regex must match the whole name, not merely occur inside it.
    • For classes, a regex, including the one in ClassCriteria.nameMatching, is matched against the fully qualified name, so anchor it with a leading .*: .*Dto matches com.company.project.OrderDto, while Dto and [A-Z].* match nothing at all.
    • For methods and fields, a regex, including the ones in FieldCriteria.nameMatching and MethodCriteria.nameMatching, is matched against the member's own name, without the declaring class: should.*, ^[A-Z][A-Z0-9_]*$.
    • A packageIdentifier is not a regex but an ArchUnit package identifier, matched against the fully qualified name with * for one segment and .. for any number: com.company.project.., ..internal...
    • An annotation matches whether it is placed directly on the class or member or inherited through another annotation, so a composed annotation such as @GetMapping counts as @RequestMapping. Only annotations kept in the class files can match, so RetentionPolicy.SOURCE annotations never do.
    • Rules that check methods or fields ignore synthetic members generated by the compiler, which cannot be changed in source code: the $values() method of every enum, bridge methods of generic overrides with erased signatures, and fields such as $assertionsDisabled. Calls made by bridge methods do not count as self-invocations either.

    methodsShouldNotReturnForClass¶

    methodsShouldNotReturnForClass(DescribedPredicate<? super JavaClass> classes, DescribedPredicate<? super JavaClass> forbiddenTypes)

    Keeps implementation types out of a layer's return signatures while allowing them to be used internally. Both class selectors can be created with com.enofex.taikai.ClassCriteria or supplied as ArchUnit predicates:

    .java(java -> java
    .methodsShouldNotReturnForClass(

        ClassCriteria.inPackage("com.company.internal..")
            .or(ClassCriteria.inPackage("com.collaborator.client.."))))

    The rule checks all methods declared in selected classes, including private methods. It checks the declared return type, nested generic arguments, wildcard and type-variable bounds, and array components. For example, banning entities rejects Entity, Entity[], List<Entity>, and ResponseEntity<List<Entity>>.     methodsShouldReturn¶

    methodsShouldReturn(DescribedPredicate<? super JavaMethod> methods, DescribedPredicate<? super JavaClass> requiredTypes)

    Like methodsShouldReturnForClass, with the same checks and limitations, but the methods are selected with method criteria.

    methodsShouldReturnForClass(DescribedPredicate<? super JavaClass> classes, DescribedPredicate<? super JavaClass> requiredTypes)

    Requires every method declared in the selected classes to have at least one matching type in its return signature. For example, require controllers to return objects whose class names end in DTO:

    .java(java -> java
    .methodsShouldReturnForClass(ClassCriteria.nameMatching(".*Controller"),
        ClassCriteria.nameMatching(".*DTO")))

    OrderDTO, OrderDTO[], List<OrderDTO>, and ResponseEntity<List<OrderDTO>> satisfy this rule. Nested generic arguments, wildcard and type-variable bounds, and array components are considered. String, Object, primitives, and void fail the DTO criterion. Both ClassCriteria.annotatedWith overloads and ClassCriteria.inPackage also work with this rule.

    Matching one type satisfies the requirement even if the signature contains other types, such as Map<Entity, OrderDTO>.     7.4 Usage Restrictions¶

    noUsageOf¶

    noUsageOf(Class<?> clazz) noUsageOf(DescribedPredicate<? super JavaClass> forbiddenTypes) noUsageOf(DescribedPredicate<? super JavaClass> classes, Class<?> clazz) noUsageOf(DescribedPredicate<? super JavaClass> classes, DescribedPredicate<? super JavaClass> forbiddenTypes)

    Forbids all usage of a type. With two arguments, the first one selects the classes to check, which lets you retire an API layer by layer, for example with ClassCriteria.inPackage(...). A type passed as Class or name is banned together with its subtypes; with forbiddenTypes, every type that matches the criteria is banned, for example a whole package. Classes that match forbiddenTypes themselves are not checked, so the classes of a banned package may still use each other.

    .java(java -> java
    .noUsageOf(Date.class)
    .noUsageOf(ClassCriteria.inPackage("com.company.project.domain.."), Calendar.class)
    .noUsageOf("com.company.legacy.UnwantedClass")
    .noUsageOf(ClassCriteria.annotatedWith(Entity.class), Date.class)
    .noUsageOf(ClassCriteria.inPackage("com.company.legacy.."))
    .noUsageOf(ClassCriteria.inPackage("..domain.."),
        ClassCriteria.inPackage("org.springframework.web..")))

    Use this rule to keep HTTP exceptions out of service and repository packages, including unchecked exceptions constructed without a throws declaration:

    .java(java -> java
    .noUsageOf(ClassCriteria.inPackage("com.company.service.."),
        "org.springframework.web.server.ResponseStatusException")
    .noUsageOf(ClassCriteria.inPackage("com.company.repository.."),
        "org.springframework.web.server.ResponseStatusException"))

    The restriction includes subclasses and bans every dependency on the exception: construction, declarations, catches, fields, and other references. It is a layer dependency rule, not an analysis of which exceptions might propagate from called methods. methodsShouldNotDeclareException only checks throws declarations and does not catch unchecked exceptions thrown without one.

    Forbids System.out and System.err in favor of a logging framework.

    With one argument, nothing may import classes matching the criteria; use ClassCriteria.inPackage(...) to ban a package. With two, only classes matching the first criteria are constrained. As with noUsageOf, classes that match the disallowed criteria themselves are not checked, so the classes of a banned package may still import each other.

    .java(java -> java
    .imports(imports -> imports
        .shouldNotImport(ClassCriteria.inPackage("com.company.project.legacy.."))
        .shouldNotImport(ClassCriteria.nameMatching(".*Service"),
            ClassCriteria.nameMatching("com.company.project.SpecificException"))
        .shouldNotImport(ClassCriteria.annotatedWith(Deprecated.class))
        .shouldNotImport(ClassCriteria.inPackage("..domain.."),
            ClassCriteria.inPackage("org.springframework.web.."))))

    A one-argument ban applies to every class outside the banned package, including the module that owns it. To keep a module's internal package private to that module, constrain only the classes outside the module:

    .java(java -> java
    .imports(imports -> imports
        .shouldNotImport(
            DescribedPredicate.not(ClassCriteria.inPackage("com.company.project.order..")),
            ClassCriteria.inPackage("com.company.project.order.internal.."))))

    10.1 General¶

    noAutowiredFields¶

    Fields must not be annotated @Autowired; use constructor injection, which keeps dependencies explicit and objects testable without a container.

    .spring(spring -> spring
    .noAutowiredFields())

    noSelfInvocationOfProxiedMethods¶

    noSelfInvocationOfProxiedMethods() noSelfInvocationOfProxiedMethods(Collection<String> annotationTypes)

    Spring implements @Transactional, @Async, caching, method security and retries by wrapping the bean in a proxy. A call such as this.save() targets the bean instance directly rather than the proxy, so the annotation on the called method is silently ignored: no transaction is started, no thread is switched, no cache is consulted, no security check runs. The proxy is only involved when the call arrives from another bean.

    @Service
class OrderService {

  void process(Order order) {
    save(order); // the proxy is bypassed, @Transactional has no effect
  }

  @Transactional
  public void save(Order order) {
  }
}

    .spring(spring -> spring
    .noSelfInvocationOfProxiedMethods())

    By default these annotations are checked. None of them has to be on the classpath:

    • org.springframework.transaction.annotation.Transactional
    • jakarta.transaction.Transactional
    • org.springframework.scheduling.annotation.Async
    • org.springframework.cache.annotation.Cacheable
    • org.springframework.cache.annotation.CacheEvict
    • org.springframework.cache.annotation.CachePut
    • org.springframework.security.access.prepost.PreAuthorize
    • org.springframework.security.access.prepost.PostAuthorize
    • org.springframework.retry.annotation.Retryable

    Pass a collection of fully qualified names to replace that list:

    .spring(spring -> spring
    .noSelfInvocationOfProxiedMethods(List.of(
        "org.springframework.transaction.annotation.Transactional",
        "org.springframework.scheduling.annotation.Async")))

    Note

    Only annotations declared on the called method are considered; class-level annotations are ignored. Because the receiver of a call cannot be resolved statically, calls on another instance of the same class, such as the self-injection workaround, are reported too. Exclude those classes with a Configuration:

    .spring(spring -> spring
    .noSelfInvocationOfProxiedMethods(
        Configuration.of(List.of(OrderService.class))))

    .spring(spring -> spring

    namesShouldMatch(String regex) those classes match a regex 
    .quarkus(quarkus -> quarkus
    .panache(panache -> panache
        .shouldBeAnnotatedWithEntityWhenActiveRecordPattern()
        .namesShouldEndWithRepository()))

    11.4 AI Services¶

    Applies to classes annotated @RegisterAiService (Quarkus LangChain4j).

    Rule Enforces
    namesShouldEndWithAssistantOrService() name ends with Assistant or Service
    namesShouldMatch(String regex) name matches a regex
    shouldBeAnnotatedWithApplicationScoped() AI services carry @ApplicationScoped
    shouldNotUseToolsAttributeInAiService() tools are not declared via the tools attribute 
    .quarkus(quarkus -> quarkus
    .ai(ai -> ai
        .namesShouldEndWithAssistantOrService()
        .shouldBeAnnotatedWithApplicationScoped()
        .shouldNotUseToolsAttributeInAiService()))

    shouldNotUseToolsAttributeInAiService steers you towards @Toolbox on the method, which scopes tools per call instead of per service.

    12. Recommended Starter Configuration¶

    A reasonable baseline for a new Spring Boot project. It is deliberately conservative: every rule here is one most teams already agree on. Add the stricter rules once this passes.

    class ArchitectureTest {

  @Test
  void shouldFulfillConstraints() {
    Taikai.builder()
        .namespace("com.company.project")
        .failOnEmpty(true)
        .java(java -> java
            .noUsageOfDeprecatedAPIs()
            .noUsageOfSystemOutOrErr()
            .fieldsShouldNotBePublic()
            .finalClassesShouldNotHaveProtectedMembers()
            .methodsShouldNotDeclareGenericExceptions()
            .utilityClassesShouldBeFinalAndHavePrivateConstructor()
            .serialVersionUIDFieldsShouldBeStaticFinalLong()
            .classesShouldImplementHashCodeAndEquals()
            .imports(imports -> imports
                .shouldHaveNoCycles()
                .shouldNotImport(ImportPatterns.shaded()))
            .naming(naming -> naming
                .packagesShouldMatchDefault()
                .classesShouldNotMatch(".*Impl")
                .constantsShouldFollowConventions()
                .enumConstantsShouldFollowConventions()
                .interfacesShouldNotHavePrefixI()))
        .logging(logging -> logging
            .loggersShouldFollowConventions(Logger.class, "logger", List.of(PRIVATE, FINAL)))
        .test(test -> test
            .junit(junit -> junit
                .classesShouldEndWithTest()
                .classesShouldBePackagePrivate(ClassCriteria.nameMatching(".*Test"))
                .classesShouldNotBeAnnotatedWithDisabled()
                .methodsShouldBePackagePrivate()
                .methodsShouldNotBeAnnotatedWithDisabled()
                .methodsShouldNotDeclareExceptions()
                .methodsShouldContainAssertionsOrVerifications()))
        .spring(spring -> spring
            .noAutowiredFields()
            .noSelfInvocationOfProxiedMethods()
            .boot(boot -> boot
                .applicationClassShouldResideInPackage())
            .configurations(configurations -> configurations
                .namesShouldEndWithConfiguration())
            .controllers(controllers -> controllers
                .namesShouldEndWithController()
                .shouldBeAnnotatedWithRestController()
                .shouldBePackagePrivate()
                .shouldNotDependOnOtherControllers()
                .shouldNotDependOnRepositories())
            .services(services -> services
                .namesShouldEndWithService()
                .shouldBeAnnotatedWithService()
                .shouldNotDependOnControllers())
            .repositories(repositories -> repositories
                .namesShouldEndWithRepository()
                .shouldBeAnnotatedWithRepository()
                .shouldNotDependOnServices()
                .shouldNotDependOnControllers())
            .transactional(transactional -> transactional
                .methodsShouldBePublic()
                .shouldNotBeSelfInvoked()
                .shouldNotBeUsedInControllers()))
        .build()
        .checkAll();
  }
}

    Adopting this on an existing codebase will usually produce violations. Two ways to stage the rollout:

    • Run checkAll() to get the full list, then add the offenders to excludeClasses or a per-rule Configuration and work the list down.
    • Enable the rule groups one at a time, committing each as it goes green.

    13. Complete Example¶

    The configuration Taikai applies to its own codebase, from ArchitectureTest.java:

    import static com.enofex.taikai.java.ImportPatterns.lombok;
import static com.enofex.taikai.java.ImportPatterns.shaded;
import static com.tngtech.archunit.core.domain.JavaModifier.FINAL;
import static com.tngtech.archunit.core.domain.JavaModifier.STATIC;

class ArchitectureTest {

  @Test
  void shouldFulfillConstraints() {
    Taikai.builder()
        .namespace("com.enofex.taikai")
        .java(java -> java
            .noUsageOfDeprecatedAPIs()
            .noUsageOfSystemOutOrErr()
            .noUsageOf(Date.class)
            .noUsageOf(Calendar.class)
            .noUsageOf(SimpleDateFormat.class)
            .fieldsShouldHaveModifiers(FieldCriteria.nameMatching("^[A-Z][A-Z0-9_]*$"),
                List.of(STATIC, FINAL))
            .classesShouldImplementHashCodeAndEquals()
            .finalClassesShouldNotHaveProtectedMembers()
            .utilityClassesShouldBeFinalAndHavePrivateConstructor()
            .methodsShouldNotDeclareGenericExceptions()
            .fieldsShouldNotBePublic()
            .serialVersionUIDFieldsShouldBeStaticFinalLong()
            .classesShouldResideInPackage("com.enofex.taikai..")
            .imports(imports -> imports
                .shouldHaveNoCycles()
                .shouldNotImport(ClassCriteria.inPackage("org.springframework.core.annotation.."))
                .shouldNotImport(ClassCriteria.inPackage("jakarta.annotation.."))
                .shouldNotImport(ClassCriteria.inPackage("javax.annotation.."))
                .shouldNotImport(ClassCriteria.inPackage("org.jetbrains.annotations.."))
                .shouldNotImport(shaded())
                .shouldNotImport(lombok()))
            .naming(naming -> naming
                .packagesShouldMatchDefault()
                .fieldsShouldNotMatch(".*(List|Set|Map)$")
                .classesShouldNotMatch(".*Impl")
                .classesShouldMatch(ClassCriteria.assignableTo(AbstractConfigurer.class),
                    ".*Configurer")
                .classesShouldMatch(ClassCriteria.implementing(Configurer.class), ".*Configurer")
                .interfacesShouldNotHavePrefixI()
                .constantsShouldFollowConventions()))
        .build()
        .checkAll();
  }
